# Sign-only rule engine: design and execution boundary

## Agreed scope

- Runtime rule files are limited to the canonical sign codes mapped from the 100 YOLO26s VTSDB classes. Other QCVN signs remain in the source catalog but have no executable rule in this runtime.
- Answer sign-meaning and sign-based permission/limit questions.
- Consider traffic signs and supplementary signs only. Other question types remain on the existing LLM pipeline.
- Model all vehicle classes; actor scope must come from the legal provision, not from an assumed universal class.
- Return `UNKNOWN` or `CONDITIONAL` and identify unresolved facts when evidence is insufficient.
- Never infer `ALLOWED` merely because no prohibition matched.
- Rule verification status is retained as provenance metadata but does not block execution. A rule must still have a recorded legal-basis reference to run.

## Runtime layers

1. `OfficialSignCatalog` normalizes only code typography and looks up sign meaning/provenance. It does not consult LawDB. Unreviewed entries return status `unverified`; ambiguous visual identity returns candidate meanings without choosing one.
2. `Intent` describes the requested answer, action, actor, and target. `TrafficFacts` contains image observations, OCR, system/query context, confidence, and explicit supplementary-to-main-sign links.
3. Declarative rules in `src/core/symbolic/catalogs/qcvn_41_2024_rulebook_draft.json` plus curated additions in `src/core/symbolic/catalogs/qcvn_41_2024_rule_drafts.json` store only rule ID, trigger sign codes, actions, actor scope/exclusions, conditions, outcome, effects, legal basis, verification status, and reason. Permission-check intent is implicit for every rule; registry metadata and schema version are not repeated per rule. Current YOLO26s VTSDB100 scope: 118 curated drafts and 121 runtime rules after merging the base rulebook; verification status is recorded but does not gate execution.
4. The evaluator finds candidates by sign/action/actor, evaluates conditions, and emits a per-rule trace. Missing and ambiguous conditions never become false or permission by default.

Vehicle grouping is centralized in `src/core/symbolic/vehicle_taxonomy.py`, using Law 36/2024/QH15 Article 34(1)-(5): motor vehicles, non-motor vehicles, and special-use machines are distinct groups. The taxonomy includes the statutory four-wheel passenger/goods vehicle, bicycle-machine/electric-bicycle, wheelchair, cycle-rickshaw, construction/agricultural/forestry machine, tractor, tractor-towed trailer, special-function machine, and defense/security special-purpose classes. The intent schema keeps `actor` to common classes (`motorcycle`, `moped`, `automobile`, `passenger_car`, `bus`, `truck`, `tractor_unit`, `other_motor_vehicle`, and `non_motor_vehicle`), plus `pedestrian` and `unknown`; rule evaluation recovers the legally detailed class from the original query and checks it against this taxonomy. Taxi/priority/emergency are actor labels or statuses, not independent legal classes; a generic mobility aid is not presumed to be a wheelchair. Classes described only as legally “similar” remain unresolved unless a reviewed subtype is supplied.
5. Aggregation is conservative. No applicable rule means `UNKNOWN`, not `ALLOWED`. Conflicting applicable rules remain unresolved unless a precedence rule resolves them.

## Simplified runtime conditions

Rules evaluate conditions when their facts are available. A missing scene-assessment fact no longer blocks a rule: the evaluator skips it and records `skipped_unobservable_scene_fact` in the trace. This applies to lane assignment, obstruction presence, approach/arrival at a sign or stop line, intersection geometry/control, traffic conflicts, and confirmation that every sign in the scene was detected. `sign_effective_scope_confirmed` is not required. Sign and query facts remain active, including speed/weight/size limits, date and time windows, distance/direction scopes, and prohibited vehicle classes. If skipping an unobservable condition would otherwise produce a definitive `ALLOWED` or `PROHIBITED` result that depends on that scene detail (for example, an unknown lane marking), the result is downgraded to `CONDITIONAL` and no permission effect is emitted. Rules whose legal outcome is inherently conditional (for example, yielding to oncoming traffic) remain `CONDITIONAL` without adding a missing-scene fact.

If an identified sign has no rule for the requested intent/action, the reasoner adds an explicit `COVERAGE_GAP_<observation>` evaluation naming the missing `sign_rule_coverage:<code>` or `intent_action_scope_coverage:<code>`. An unresolved gap alongside a decisive rule result downgrades the combined result to `CONDITIONAL`; a known `not_applicable` result does not create a spurious gap. This prevents an unruled sign from disappearing merely because another sign matched.

Permission/limit evaluation also requires an explicit `TrafficFacts.sign_inventory_status` (`complete`, `partial`, or `unknown`). It defaults to `unknown`; `complete` is accepted only with provenance in `sign_inventory_evidence` (a nonempty `source` and `evidence`). When status is not `complete`, a matched permission rule is downgraded to `CONDITIONAL` with `complete_sign_inventory` listed as missing. This prevents a crop containing a primary sign from being treated as proof that no scope-changing supplementary sign was present. A full-scene detector or reviewer must explicitly attest that sign and supplementary-sign inventory is complete before the engine can issue a definitive result from that scene.

`TrafficRule` rejects `outcome: ALLOWED` unless the rule has an explicit `permit_action` or `allow_direction` effect. Any effect that depends on a value predicate must also declare a required condition for that fact. This prevents an empty/missing rule match or an unresolved numeric fact from silently becoming affirmative permission.

Vehicle identity alone does not establish priority-vehicle status. If a sign rule excludes priority vehicles but the intent identifies only an emergency vehicle, the evaluator returns `UNKNOWN` with `priority_vehicle_status` missing instead of applying the exception automatically.

The evaluator extracts evidence-linked observations from identified S.501/S.502 distances, S.508 printed time ranges/day parity, and S.509a height text. These produce typed predicates (`effect_length_m`, `distance_to_object_m`, `supplementary_time_window`, `supplementary_calendar_parity`, `safe_height_limit_m`); they do not themselves create legal outcomes. OCR values without explicit medium/high OCR confidence stay `ambiguous`. Rule conditions can compare two facts with `equals_fact`, compare numeric fact thresholds, or compare an extracted S.508 interval with a resolved `observed_at` using `time_window_contains_now`; exact interval endpoints remain `CONDITIONAL` because the endpoint convention is not assumed. Detected but unlinked/low-confidence S.501–S.506/S.508–S.509 panels make permission results conditional, while standalone S.507 and S.510 are not misclassified as scope panels.
